pianolog: an always-on MIDI recorder

A small box that stays plugged into a digital piano, saves every take as a MIDI file in its own memory and on a memory card, and serves a web page where you browse and play them from your phone. After the first setup it updates over Wi-Fi.

Read first

The firmware compiles and its file-handling logic passes tests on a PC. Nobody has run it on a real board yet: you are the first. Section 8 lists exactly what is and is not verified, and section 7 covers the likely first-boot problems.

1. What you are building

The board is a Waveshare ESP32-P4-NANO. It was chosen because it already carries everything the job needs: a RISC-V ESP32-P4 with a USB host port wired to a Type-A socket, a microSD slot, and an ESP32-C6 for Wi-Fi. The whole build is the board, a card and two cables.

3. Prepare the memory card (optional)

The recorder works without a card: takes are always recorded into the board's own memory first. A card is the long-term archive, and takes are moved onto it automatically.

  1. Format the card as FAT32. Cards up to 32 GB come that way. A 64 GB card arrives as exFAT, which the recorder cannot read, and needs reformatting.

  2. Optionally, create a text file named pianolog.txt in the top folder of the card with your home Wi-Fi:

    wifi_ssid=YourNetworkName
wifi_pass=YourPassword

    Usually you won't need it: the setup page in section 5 is easier. The network must be 2.4 GHz.

  3. Push the card into the slot on the board until it clicks.

4. Load the firmware

Do this once, from a computer, through the board's USB-C port. Later versions go over Wi-Fi (section 6). The download contains two ready-made images because ESP32-P4 chips before and after revision 3.0 are not compatible with each other.

  1. Install the flashing tool (needs Python 3):

    pip install esptool

  2. Connect the board's USB-C port to the computer and ask the chip for its revision:

    python -m esptool --chip esp32p4 chip-id

    Look for a line containing ESP32-P4 (revision v3.1) or similar. If no serial port is found, install the USB-serial driver linked from Waveshare's board page. If the tool cannot connect, hold BOOT, tap RESET, release BOOT, and retry.

  3. Flash the image that matches. Revision 3.0 or higher:

    python -m esptool --chip esp32p4 -b 460800 write-flash 0x0 firmware/pianolog-p4-rev3.bin

    Revision below 3.0 (0.x or 1.x):

    python -m esptool --chip esp32p4 -b 460800 write-flash 0x0 firmware/pianolog-p4-rev1.bin

  4. Watch the first boot. Any serial terminal at 115200 baud works; with ESP-IDF installed, idf.py monitor is the most convenient. A healthy start prints sd: flash storage mounted, then net: joined or net: setup network.

Ready-made images use placeholder secrets

The images in firmware/ contain the update token CHANGE-ME-ota-token and the setup-network password pianolog-setup, both printed in this manual. They are fine for a first test. Before the recorder lives on a shared network, build your own with real values (below).

Building it yourself

Set your own update token, setup-network password and, if you like, a built-in home network in sdkconfig.secrets: copy sdkconfig.secrets.example to that name and edit it. Git ignores the file, so real passwords stay out of the repository. Then install ESP-IDF 5.5.3 or a later 5.5 release, then run idf.py set-target esp32p4 and idf.py build flash monitor in the project folder. The README explains the extra option for older chip revisions and the settings menu for pins.

5. Connect and use

  1. Run the instrument cable from the piano's USB socket (often labelled USB TO HOST) to the board's Type-A socket. With an interface cable, one of its round plugs goes into the instrument's MIDI OUT; the plugs are labelled, and labelling conventions differ between brands, so follow the cable's leaflet. Power the board from the charger through USB-C. The order does not matter, and the piano can be switched off: the recorder notices when it comes on.

  2. Play something, then stop for a minute.

  3. The first time, about 30 seconds after power-on, the recorder opens its own Wi-Fi network called pianolog. Join it from your phone with the password pianolog-setup (or your own, if you built the firmware yourself), open http://192.168.4.1/setup, choose your home network and type its password. The recorder joins it and closes its own network about 15 seconds later. It does the same whenever it cannot reach any known network.

  4. With the phone back on your home Wi-Fi, open http://pianolog.local.

  5. Tap a take to see its piano roll and hear it through the phone. Download saves the MIDI file. The star marks takes worth keeping.

Status light (optional)

Push three female jumper wires onto the LED's legs and onto the header pins labelled GPIO21 (the LED's data in, DI), 3V3 (VDD) and GND. The fourth leg (DO) stays free. Leg order differs between makers, so follow the seller's pinout, and cover the bare legs with heat-shrink or tape.

How it decides what a take is

  • A take starts with the first key you press and ends after 60 seconds of silence. Change gap_s in pianolog.txt to taste.
  • Takes are filed by day: rec/2026-11-13/20-31-05_0185s_0412n.mid is a take started at 20:31:05, 185 seconds long, 412 notes. The card can also be read directly in a computer.
  • Each take is recorded into the board's own memory, which is built to survive power cuts. Once the take ends it is copied to the card, checked, and only then removed from the board. Takes not yet copied are marked internal on the page.
  • Unplugging the power at any moment is fine: at most the last two seconds of a take are lost, and an interrupted take is completed at the next start.
  • Without a card, when the board's memory is nearly full, the oldest takes are deleted to make room. Starred takes go only when nothing else is left.
  • Privacy works the way it does on any recorder that never stops: anyone who plays is recorded, and anyone on your Wi-Fi can open the page. Pull the USB-C plug to stop it.

6. Updates over Wi-Fi

After the first flash, new versions go over the network. Laptop and recorder must be on the same Wi-Fi, and the network must let devices see each other; home networks do, guest and office networks often don't.

  1. Build the new version in the project folder: idf.py build.

  2. Send it:

    tools/ota.sh

    It uploads build/pianolog.bin to http://pianolog.local with the update token from your build settings. To use the recorder's own network instead: tools/ota.sh build/pianolog.bin 192.168.4.1.

  3. The recorder checks the file, closes any take in progress, and restarts into the new version within a few seconds.

If the new version is broken

A fresh version must reach the network within two minutes of starting. If it crashes or never gets there, the board goes back to the previous version by itself, so a bad update does not mean getting the cable out.

7. If something does not work

SymptomLikely cause and fix
Flashing stops with a chip revision error, or the board restarts in a loopThe other image is the right one for your chip. Repeat step 3 of section 4 with it.
Page says no cardRecording still works without it. Card is exFAT or not seated. Reformat as FAT32. If a FAT32 card is still not found, the card power wiring differs from what the firmware assumes: see PL_SD_LDO_CHAN and PL_SD_EN_GPIO in the settings menu and Waveshare's SD example.
Page says no piano detectedCheck the cable is in the piano's TO HOST socket and the piano is on. The serial log shows usb: MIDI device connected on success. If nothing at all is logged when plugging in, measure whether the Type-A socket supplies 5 V; this could not be confirmed from the documentation. An interface cable depends on that power, so if it is missing use a USB power-injector (Y) cable.
Log says the device has no MIDI IN endpointThe instrument is not class-compliant USB MIDI (some older models need a vendor driver). Connect it through a USB-MIDI interface cable from its round MIDI OUT socket instead.
pianolog.local does not openSome Android versions and networks do not resolve .local names. Use the address printed in the serial log or shown in your router's device list.
Wi-Fi never starts, log shows esp_hosted errorsThe ESP32-C6 on the board runs factory firmware that is too old for the driver in this build. Update it following the esp_hosted documentation. Recording keeps working meanwhile; read the card in a computer.
tools/ota.sh answers 401The token on the board differs from the one in your build settings. If the board runs a ready-made image, its token is CHANGE-ME-ota-token: run PIANOLOG_OTA_TOKEN=CHANGE-ME-ota-token tools/ota.sh.
Update says no OTA slotThe board still has the partition layout of firmware 0.1. Flash once more by cable (section 4).
After an update the old version is backThe new version did not reach the network within two minutes and was rolled back. Check its log over the cable.
The setup page saved the network but the recorder never joins itWrong password, or a 5 GHz-only network. The setup network stays up, so join it again and retry.
Take times are wrong, or takes appear under Clock not setThe clock comes from the internet, or from your phone when the page is open. Takes made before either was available cannot be dated.

8. What has been verified

Checked on a PC

  • Both firmware images build with ESP-IDF 5.5.6, with update rollback enabled.
  • MIDI parsing, file writing and power-loss repair pass unit tests, including a cut at every possible byte position.
  • Moving takes to the card survives a simulated power cut before and after the final rename; the overwrite-oldest rule keeps starred takes and the live take.
  • Files produced open correctly in an independent MIDI library.
  • The web pages were exercised in a phone-sized browser against a simulated recorder: listing, playback, starring, opening a take that is still recording, and the Wi-Fi setup form.

Not checked: needs your board

  • Detection of a real piano on the Type-A port.
  • Card power and Wi-Fi co-processor behaviour on this exact board.
  • A real update and rollback, and network scanning while the setup network is up.
  • Timing accuracy and behaviour over days of running.

A printed case is deliberately left out of this revision. Clone and batch differences move connectors by a millimetre or two, so the case should be drawn from caliper measurements of the board you receive.
